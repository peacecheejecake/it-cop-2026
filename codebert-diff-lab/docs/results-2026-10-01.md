# CodeBERT Diff Lab: interim results (M0–M4) — 2026-10-01

> **Correction (2026-10-02):** the text-variant numbers here (B1–B4) were measured on package text that depends on the label. B0-LR and B0-LGBM are not affected. See [`leak-finding-2026-10-02.md`](leak-finding-2026-10-02.md) and [`v4-correction-plan.md`](v4-correction-plan.md).

This document summarizes the results of implementing spec v0.2 (`docs/spec-v0.2/`) and running M0 through M4. All performance numbers are **selection-validation** values on public validation. **The public test is still sealed**, and no conclusion in this document is final.

## 1. Summary

- **Current reference study: `public-comparison-v3`** (`configs/studies/public-comparison-v3.yaml`). Under the original v2 protocol, the encoder and head shared lr 1e-5, so the head was under-trained. v3 separates the two learning rates (encoder 1e-5, head 1e-3) and reruns every implemented variant.
- v3 validation AP ordering: **B3-S 0.687 > B4-S 0.674 > B2-S 0.616 > B1-TFIDF-S 0.546 > B0-LR 0.319 > B0-LGBM 0.211**.
- Full fine-tuning (B3-S) adds +0.071 over frozen CodeBERT (B2-S). The frozen representation adds +0.070 over character n-gram TF-IDF (B1).
- **10M-token diff MLM continued pre-training (B4-S) showed no added value** over B3-S (−0.013, lower on all three seeds). The v2 result (B4 > B3 by +0.024) appears to be an artifact of the under-trained head.

## 4. Protocol change history (v2 → v3)

| variant | v2 AP (shared lr 1e-5, max 20 epochs) | v3 AP | Change |
|---|---|---|---|
| B2-S | 0.377 ± 0.005 (still rising at the 20-epoch cap) | 0.616 ± 0.011 | +0.239 |
| B3-S | 0.527 ± 0.024 | 0.687 ± 0.008 | +0.160 |
| B4-S | 0.551 ± 0.008 (seed 43/44 from logs only) | 0.674 ± 0.014 | +0.123 |

- The trigger: v2's B2-S (experiment 007) was still improving at the 20-epoch cap. A supplementary sensitivity run that changed only the head lr (1e-3, max 100 epochs; experiment 008, `b2-head-sensitivity-v1`) gave B2-S AP 0.616.
- v3 was registered **before any public-test access**. The single head-lr setting is applied identically to B2–B5. Disclosure: lr 1e-3 was informed by the validation sensitivity run above. The configurations seen on validation are v2 and v3 only.
- The v2 results (experiments 006–008) are kept only as the record of the initial protocol and are not mixed into the v3 comparison.

## 5. Interpretation and limitations

1. **Selection bias**: neural variants pick the checkpoint epoch on validation, and the epoch-to-epoch AP swing is about ±0.03. B2-S searches 19–32 epochs while B3/B4 search only 6–8, so the number of selection opportunities also differs. The differences above are tentative. The final comparison will use paired differences and a project-level bootstrap on the test set after freeze.
2. **The value of CPT (RQ2)**: under this setup (10M tokens, the same downstream protocol), there is no benefit. The gap is about the size of the seed sd (0.008–0.014), so the statement is "no benefit observed", not "harmful". Per the spec, a no-effect result is a valid result. Scaling to 50M/100M tokens should be decided based on the validation trend.
3. **CPT-dev diagnostic**: even after group-based selection, one CPT-train row matches CPT-dev text after evidence truncation. Dev loss is only a diagnostic and is not used for model selection.
4. **Data limitations**: the provided split is not chronological. The license is unverified. Code lines are stored as sets, so their order is lost; the adapter sorts them.
5. **Overfitting**: B3/B4 peak in 1–3 epochs and then overfit quickly (training loss 0.24 → 0.04).

## 6. External review and fixes

The project was reviewed by the Codex CLI in read-only mode. The full text is on branch `exp/008-dl-m4-mlm-cpt`, under `reviews/`.

- **No direct leakage** of validation/test labels into training.
- **Fixes on main** (`46b1a28`, `9fd51de`):

| Finding | Fix |
|---|---|
| CUDA resume RNG restore failure | Load checkpoints on CPU; CUDA resume tests pass on the pod |
| Missing lineage cross-checks | `lineage.py`: approval → snapshot → split → evidence → tokenizer, plus provided valid/test membership |
| Selection bias | `evaluation_role: selection_validation` tag and `selection_events` ledger entries |
| Duplicate CPT-dev text | `upstream-clean2` |
| Weak provenance | Source digest in run IDs; unknown code SHA rejected; completed runs reused only after artifact-hash checks; weights pinned by sha256 |
| Non-atomic checkpoints | Immutable generations plus an atomic pointer |
| Metric null definitions | AP is null only when there are no positives; empty cohorts handled |
| Run folder | `metrics.jsonl`, token accounting, `reports/summary.md`; unmeasured latency recorded as null |
| Tests | Strengthened: 42 → 60 |

- **Bug found during the rerun**: importing torch and LightGBM in the same process loads two OpenMP runtimes and causes a segfault. torch is now imported only for neural variants.

## 8. Reproduction

```bash
cd codebert-diff-lab
uv sync --system-certs --extra lgbm --extra neural --extra dev
uv run diff-lab data import --source jit-defects4j --archive <data.zip> --approval configs/sources/jit-defects4j.yaml --snapshot-id jitd4j-audit1
uv run diff-lab data audit --snapshot-id jitd4j-audit1
uv run diff-lab data split --snapshot-id jitd4j-audit1 --split-id upstream-clean2
uv run diff-lab evidence build --study configs/studies/public-comparison-v3.yaml
uv run diff-lab experiment run --study configs/studies/public-comparison-v3.yaml --models B0-LR,B0-LGBM,B1-TFIDF-S --seeds 42,43,44
uv run diff-lab experiment run --study configs/studies/public-comparison-v3.yaml --models B2-S,B3-S,B4-S --seeds 42,43,44   # CUDA
```
